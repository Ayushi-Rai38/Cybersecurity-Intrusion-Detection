# 🛡️ CyberShield IDS — Cybersecurity Intrusion Detection System

**PySpark MLlib · FastAPI · React + Vite · UNSW-NB15 Dataset**

A machine-learning-powered network intrusion detection system that classifies network traffic as **Normal** or **Attack** using a Random Forest Classifier trained on the UNSW-NB15 dataset.

## 🚀 Setup & Run

### 1. Clone & Install Python Dependencies

```bash
cd Cybersecurity-Intrusion-Detection
python -m venv .venv

# Windows
.\.venv\Scripts\activate

# Linux/Mac
source .venv/bin/activate

pip install -r requirements.txt
```

### 2. Train the Model (run once)

```bash
python main.py
```

This takes ~2 minutes and generates:
- `outputs/metrics.json` — model evaluation metrics
- `outputs/predictions.csv` — 82,332 test predictions
- `models/intrusion_rf_model/` — saved PipelineModel

### 3. Start the Backend API

```bash
python api.py
```

- API at: http://localhost:5000
- Swagger docs at: http://localhost:5000/docs

### 4. Start the React Frontend

```bash
cd frontend
npm install       # first time only
npm run dev
```

- Dashboard at: http://localhost:5173

## 🔬 ML Pipeline (main.py — 6 Tasks)

| Task | Description |
|------|-------------|
| 1    | Load UNSW-NB15 training and testing CSVs with PySpark |
| 2    | Data preprocessing — handle missing values, cast types |
| 3    | Feature engineering — StringIndexer + OneHotEncoder for categorical columns (proto, service, state) |
| 4    | VectorAssembler — combine all numeric + encoded features |
| 5    | Train Random Forest Classifier (100 trees, max depth 15) |
| 6    | Evaluate on test set — accuracy, precision, recall, F1, ROC-AUC, confusion matrix |

**Key design decisions:**
- `id` and `attack_cat` excluded from features (data leakage prevention)
- `label` (0/1) used as the binary target
- Official train/test split preserved — no random mixing
- `attack_cat` retained in predictions for analysis only

## 🎓 Viva Q&A Reference

**Q: Why Random Forest?**
A: Handles mixed feature types, resistant to overfitting with 100 trees, provides feature importance, works well with tabular data.

**Q: How do you prevent data leakage?**
A: `id` (row identifier) and `attack_cat` (derived from label) are excluded from model features. Only `label` (0/1) is the target.

**Q: Why keep the official train/test split?**
A: The UNSW-NB15 authors curated separate sets. Random splitting would mix attack distributions and inflate metrics.

**Q: What preprocessing is done?**
A: Missing values filled (0 for numeric, '-' for categorical). StringIndexer + OneHotEncoder for proto/service/state. VectorAssembler combines all features.

**Q: How does the predict endpoint work?**
A: It lazy-loads the saved PipelineModel into Spark, creates a single-row DataFrame from input, runs model.transform(), and returns the prediction + probability.

**Q: What is ROC-AUC?**
A: Area Under the Receiver Operating Characteristic curve. Measures model discrimination across all classification thresholds. 0.9793 means 97.93% probability that a random attack is scored higher than a random normal record.

## 📝 Notes

- The UNSW-NB15 dataset does **not** contain timestamps or sport/dsport columns in these CSVs
- The dashboard does **not** fabricate time-based trends
- The API serves **pre-computed** results from `outputs/` — it does NOT retrain on every request
- The Predict tab loads Spark lazily on first use (~30 seconds), then caches the model

## 📋 Project Overview

This project builds a complete **Intrusion Detection System (IDS)** using machine learning on real network traffic data. It classifies each network connection as **Benign** or **Suspicious** (attack) using a Random Forest model trained with Apache Spark's MLlib.

### ML Tasks Implemented (Question 62)
| # | Task | Status |
|---|------|--------|
| 367 | Load UNSW-NB15 dataset into Spark DataFrame, handle nulls/missing values | ✅ |
| 368 | Encode categorical features (proto, service, state) using StringIndexer + OneHotEncoder; assemble feature vector | ✅ |
| 369 | Build Random Forest classifier using PySpark MLlib | ✅ |
| 370 | Evaluate with Precision, Recall, F1-score, ROC-AUC, and Confusion Matrix; handle class imbalance with class weights | ✅ |
| 371 | Apply model to test set and generate intrusion-risk predictions | ✅ |
| 372 | Dashboard: traffic volume, predicted alerts, actual vs. predicted attacks, attack categories | ✅ |

### Class Imbalance Handling
UNSW-NB15 training set is imbalanced (32% normal, 68% attack). We handle this by computing **per-class weights**:

```
weight(class) = total_samples / (n_classes × count(class))
```

These weights are passed to `RandomForestClassifier(weightCol=...)` so the model pays more attention to the minority class.

## 🎓 Viva / Evaluation Q&A

**Q: Why Random Forest?**  
A: Random Forest is an ensemble of decision trees that reduces overfitting, handles mixed feature types well, and gives feature importance rankings — ideal for network intrusion data with 45 heterogeneous features.

**Q: How did you handle class imbalance?**  
A: Computed inverse-frequency class weights and passed them to `RandomForestClassifier(weightCol=...)`. This forces the model to penalise misclassifying the minority class more heavily.

**Q: Why exclude `attack_cat` and `id` from features?**  
A: `attack_cat` directly encodes the attack type — including it would be **data leakage** (the model would see the answer). `id` is a row index with no predictive value.

**Q: What is ROC-AUC?**  
A: Area Under the ROC Curve measures the model's ability to distinguish between classes across all decision thresholds. A value of 1.0 is perfect; 0.5 is random guessing.

**Q: What does the confusion matrix show?**  
A: Four quadrants: True Positives (correctly flagged attacks), True Negatives (correctly identified normal), False Positives (false alarms), False Negatives (missed attacks). For security, minimising False Negatives is critical.

**Q: How does the Flask API work?**  
A: `main.py` trains the model and saves outputs to `outputs/`. `api.py` reads those CSV/JSON files and serves them over HTTP. The React frontend calls these endpoints — **no retraining on API requests**.

**Q: Why React + Vite instead of Streamlit?**  
A: React gives a richer, more interactive UI with real-time filtering, pagination, and professional charting (Recharts). Vite provides fast hot-module replacement for development. This separation (React frontend + Flask backend) follows industry-standard architecture.
